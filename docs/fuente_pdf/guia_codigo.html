1. El programa en 30 segundos

Todo empieza en main_torneo.cpp. La función main() no tiene lógica del juego: es un director que llama a otras funciones en orden. Cada número te lleva a la sección que explica ese paso.

int main()
{
    srand(time(0));                              // semilla del azar          7

    Estrategia estrategias[NUM_ESTRATEGIAS];     // los 8 jugadores        5
    int ranking[NUM_ESTRATEGIAS];                // orden final             12

    int numeroRondas = leerNumeroRondas();       // pedir rondas            13

    inicializarEstrategias(estrategias);         // llenar las fichas       5
    ejecutarTorneo(estrategias, numeroRondas);   // 28 partidas             10
    calcularEstadisticas(estrategias);           // G / P / E y %           11
    ordenarRanking(estrategias, ranking);        // de mayor a menor        12

    mostrarDetalleTorneo(estrategias, ranking);  // imprimir                13
    mostrarRanking(estrategias, ranking, numeroRondas);
    mostrarGanador(estrategias, ranking);
    return 0;
}

El viaje de los datos

Piensa en el programa como una cadena de montaje. Cada función recibe el arreglo estrategias, le escribe algo y se lo pasa a la siguiente:

¿Por qué está dividido en tantos archivos? Cada archivo .h/.cpp tiene una sola responsabilidad. El .h es la “promesa” (qué funciones existen y qué reciben) y el .cpp es el “cómo”. Así, si quieres cambiar la matriz de pagos, solo tocas matriz_pagos.cpp y nada más se rompe.

2. Las constantes: por qué 8 y 201 (y por qué no hay máximo)

const int NUM_ESTRATEGIAS = 8;
const int MIN_RONDAS = 201;   // no hay MAX_RONDAS
ConstanteValor¿Dónde se usa?¿Por qué ese valor?
NUM_ESTRATEGIAS8Tamaño de estrategias, ranking, puntosContra y límite de todos los for del torneo.6 estrategias obligatorias + 2 propias.
MIN_RONDAS201leerNumeroRondasEl enunciado exige más de 200 rondas → el menor entero válido es 201.
¿Por qué constantes y no escribir 8 directamente? Si mañana agregas una novena estrategia, cambias un solo número y todos los arreglos y bucles se ajustan solos. Con el 8 escrito en 15 lugares tendrías que encontrarlos todos (y es fácil olvidar uno).
¿Por qué no hay máximo? El enunciado solo pide más de 200 rondas; no pone un límite superior, así que el programa tampoco. Eso obliga a tres decisiones:
  • Historial con memoria dinámica. char historialA[numeroRondas] no es C++ estándar, porque el tamaño se conoce recién cuando el usuario escribe. Por eso ejecutarPartida crea los historiales con new char[numeroRondas] (el tamaño exacto que se pidió) y los libera con delete[] al terminar la partida (sección 8).
  • Puntajes long long. Un int llega hasta 2 147 483 647. Con muchas rondas los puntajes pasarían ese valor y se desbordarían (Pruébalo 1). long long llega hasta unos 9,2 × 1018.
  • Vengativa sin recorrer todo el historial. Si en cada ronda se revisaran todas las rondas anteriores, con muchas rondas el torneo sería muy lento (sección 7).
El único tope práctico es que numeroRondas es un int: un número mayor que 2 147 483 647 no cabe y cin lo trata como entrada inválida. Además, mientras más rondas, más memoria y más tiempo tarda el torneo.

4. El puntero a función FuncionDecision

Esta es la idea más avanzada del programa, y también la que más simplifica todo lo demás.

typedef char (*FuncionDecision)(int numeroRonda,
                                const char historialPropio[],
                                const char historialOponente[]);

Léelo así: “FuncionDecision es el nombre de un tipo. Una variable de ese tipo guarda la dirección de una función que recibe (int, arreglo de char, arreglo de char) y devuelve un char”.

Analogía: el control remoto. El campo decidir de cada ficha es un control remoto con un solo botón. A ejecutarPartida no le importa qué televisor controla: solo aprieta el botón estrategiaA.decidir(...) y recibe una C o una T.

Sin puntero a función (lo que se evitó)

char jugadaA;
if      (estrategiaA.id == 0) jugadaA = decidirSiempreCooperar(ronda, historialA, historialB);
else if (estrategiaA.id == 1) jugadaA = decidirSiempreTraicionar(ronda, historialA, historialB);
else if (estrategiaA.id == 2) jugadaA = decidirAleatoria(ronda, historialA, historialB);
// ... 8 casos, y otra vez los 8 casos para jugadaB ...

Con puntero a función (lo que hace el programa)

char jugadaA = estrategiaA.decidir(ronda, historialA, historialB);
char jugadaB = estrategiaB.decidir(ronda, historialB, historialA);

6. La regla de los índices: N − 1 y N − 2

Las rondas se cuentan desde 1 (como las cuenta una persona), pero los arreglos en C++ empiezan en 0. De ahí salen dos reglas que aparecen en todo el código:

Quiero…Escribo…Ejemplo en la ronda 5
Guardar la jugada de la ronda actualhistorial[ronda - 1]se guarda en la posición 4
Leer la jugada de la ronda anteriorhistorial[numeroRonda - 2]se lee la posición 3 (= ronda 4)
Leer la de hace dos rondashistorial[numeroRonda - 3]se lee la posición 2 (= ronda 3)

La celda con borde amarillo es historialOponente[5 - 2]: la última jugada del rival. Las celdas con ? tienen basura (el arreglo no se inicializa), pero nunca se leen: cada estrategia solo mira posiciones menores que numeroRonda - 1.

¿Por qué Tit for Tat, Vengativa y Pavlov tienen if (numeroRonda == 1)? En la ronda 1, numeroRonda - 2 = -1. Leer historial[-1] sería leer memoria fuera del arreglo. Esa condición es una protección, no solo una regla del juego. Igual con Ojo por Dos Ojos, que necesita numeroRonda >= 3 para leer numeroRonda - 3.

7. Las 8 estrategias por dentro

Todas tienen la misma firma: reciben numeroRonda, historialPropio e historialOponente, y devuelven 'C' o 'T'.

¿Por qué srand(time(0)) está en main y no en decidirAleatoria? srand fija el punto de partida del azar. Si se llamara en cada ronda, todas las rondas del mismo segundo tendrían la misma semilla y darían la misma jugada. Se llama una sola vez al inicio y después rand() va dando números distintos.

Vengativa: “recordar para siempre” mirando solo la ronda anterior

if (numeroRonda == 1) return 'C';
if (historialOponente[numeroRonda - 2] == 'T' || historialPropio[numeroRonda - 2] == 'T')
    return 'T';
return 'C';

No tiene una variable bool yaMeTraicionaron. Hay solo dos formas de que Vengativa traicione en esta ronda:

  • El rival traicionó en la ronda anterior → la venganza empieza ahora.
  • Yo traicioné en la ronda anterior → eso solo pasa si la venganza ya había empezado, así que sigo.

La primera T del rival “enciende” la venganza, y desde ahí su propia T la mantiene encendida para siempre. La memoria es su propio historial.

¿Por qué no recorrer todo el historial del rival buscando una T? Daría el mismo resultado, pero en la ronda n habría que revisar n − 1 posiciones. En una partida eso suma 1 + 2 + … + n ≈ n² / 2 lecturas: con 100 000 rondas serían unos 5 000 millones por partida. Como ya no hay límite de rondas, se mira solo la ronda anterior: 2 lecturas por ronda, sin importar cuántas rondas se jueguen.

8. Una partida, ronda por ronda (ejecutarPartida)

void ejecutarPartida(Estrategia &estrategiaA, Estrategia &estrategiaB, int numeroRondas,
                     long long &puntosPartidaA, long long &puntosPartidaB)
{
    char *historialA = new char[numeroRondas];                         1
    char *historialB = new char[numeroRondas];
    puntosPartidaA = 0;  puntosPartidaB = 0;

    for (int ronda = 1; ronda <= numeroRondas; ronda++)
    {
        char jugadaA = estrategiaA.decidir(ronda, historialA, historialB); 2
        char jugadaB = estrategiaB.decidir(ronda, historialB, historialA); 3

        historialA[ronda - 1] = jugadaA;                                  2
        historialB[ronda - 1] = jugadaB;

        registrarJugada(estrategiaA, jugadaA);                            4
        registrarJugada(estrategiaB, jugadaB);

        int puntosRondaA;  int puntosRondaB;
        calcularPuntosRonda(jugadaA, jugadaB, puntosRondaA, puntosRondaB);  9
        puntosPartidaA += puntosRondaA;
        puntosPartidaB += puntosRondaB;
    }

    delete[] historialA;                                                1
    delete[] historialB;
}
  1. Historiales nuevos en cada partida: se crean dentro de la función, así que ninguna estrategia “recuerda” lo que pasó contra otro rival. Como no hay máximo de rondas, se piden con new char[numeroRondas]: justo el tamaño necesario, ni una celda de más. Todo lo que se pide con new hay que devolverlo con delete[]; si no, cada una de las 28 partidas dejaría memoria ocupada sin usar (una fuga de memoria).
  2. Decidir primero, guardar después: las dos estrategias deciden antes de guardar. Si se guardara jugadaA antes de que B decida, B podría ver lo que A acaba de jugar, y eso sería hacer trampa: en el dilema las decisiones son simultáneas.
  3. Los historiales se pasan al revés para B: (ronda, historialB, historialA). Para B, “propio” es el historial B y “oponente” es el A. Gracias a eso la misma función sirve para jugar de un lado o del otro.
  4. registrarJugada suma 1 a vecesC o a vecesT. Recibe la estrategia por referencia (&) para modificar la ficha original y no una copia.

9. La matriz de pagos y el paso por referencia

void calcularPuntosRonda(char jugadaA, char jugadaB, int &puntosA, int &puntosB)
{
    if      (jugadaA == 'C' && jugadaB == 'C') { puntosA = 3; puntosB = 3; }
    else if (jugadaA == 'C' && jugadaB == 'T') { puntosA = 0; puntosB = 5; }
    else if (jugadaA == 'T' && jugadaB == 'C') { puntosA = 5; puntosB = 0; }
    else                                     { puntosA = 1; puntosB = 1; }
}           // (en el código real se usan las constantes PUNTOS_...)
¿Por qué int &puntosA con &? Una función solo puede devolver un valor con return, pero aquí necesitamos devolver dos (los puntos de A y los de B). Con &, puntosA no es una copia: es otro nombre para la variable puntosRondaA de ejecutarPartida. Lo que se asigna dentro aparece afuera.
ParámetroCómo se pasa¿Por qué?
char jugadaApor valor (copia)Solo se lee; copiar un char es gratis.
int &puntosApor referenciaEs un resultado: la función lo escribe.
Estrategia &estrategiaApor referenciaejecutarPartida modifica vecesC/vecesT de la ficha original.
const Estrategia estrategias[]arreglo, de solo lecturaLas funciones mostrar… y ordenarRanking no deben modificar nada; const hace que el compilador lo impida.
Estrategia estrategias[]arreglo (siempre se comparte)En C++ un arreglo nunca se copia al pasarlo: la función trabaja sobre el original. Por eso ejecutarTorneo puede llenar los puntajes.

10. El torneo: por qué j = i + 1

for (int i = 0; i < NUM_ESTRATEGIAS; i++)
    for (int j = i + 1; j < NUM_ESTRATEGIAS; j++)
    {
        long long puntosI;  long long puntosJ;
        ejecutarPartida(estrategias[i], estrategias[j], numeroRondas, puntosI, puntosJ);

        estrategias[i].puntosContra[j] = puntosI;     // desde el punto de vista de i
        estrategias[j].puntosContra[i] = puntosJ;     // desde el punto de vista de j
        estrategias[i].puntajeTotal += puntosI;
        estrategias[j].puntajeTotal += puntosJ;
    }

Cada número de la tabla es el orden en que se juega esa partida. Solo se juega el triángulo superior:

¿Por qué j empieza en i + 1 y no en 0?
  • Si empezara en 0, se jugaría 0 contra 1 y también 1 contra 0: cada partida dos veces (56 en vez de 28) y todos los puntajes se duplicarían.
  • Si empezara en i, cada estrategia jugaría contra sí misma (la diagonal gris).
  • Con i + 1 se juega exactamente cada par una vez: 7 + 6 + 5 + 4 + 3 + 2 + 1 = 28 partidas = 8 × 7 / 2.

11. Estadísticas: victorias y porcentajes

for (int j = 0; j < NUM_ESTRATEGIAS; j++)
{
    if (j == i) continue;                                // no hubo partida contra sí misma
    long long misPuntos   = estrategias[i].puntosContra[j];
    long long puntosRival = estrategias[j].puntosContra[i];    // la celda "espejo"
    if      (misPuntos > puntosRival) estrategias[i].victorias++;
    else if (misPuntos < puntosRival) estrategias[i].derrotas++;
    else                              estrategias[i].empates++;
}

Ejemplo con i = 3 (Tit for Tat) y j = 1 (Siempre Traicionar): misPuntos = 249, puntosRival = 254 → 249 < 254 → derrotas++.

¿Por qué continue cuando j == i? puntosContra[i] de sí misma vale 0, y 0 contra 0 contaría como un empate falso. Con continue se salta esa vuelta del bucle y cada estrategia suma exactamente 7 resultados.

Porcentajes

long long totalJugadas = estrategias[i].vecesC + estrategias[i].vecesT;
if (totalJugadas > 0)
    estrategias[i].porcentajeC = 100.0 * estrategias[i].vecesC / totalJugadas;
¿Por qué 100.0 y no 100? Cuando todos los operandos son enteros (int o long long), C++ hace división entera y descarta los decimales. Con 100 * 1372 / 1750 saldría 78 en vez de 78.40; y si alguien escribiera vecesC / totalJugadas * 100, saldría 0, porque 1372 / 1750 = 0 en división entera. Al empezar con 100.0 (un double), toda la operación se hace con decimales: 100.0 * 1372 / 1750 = 78.40.
¿Por qué el if (totalJugadas > 0)? Para no dividir entre cero. En este programa nunca pasa (siempre hay jugadas), pero es una protección barata.

12. El ranking: burbuja sobre índices

for (int i = 0; i < NUM_ESTRATEGIAS; i++) ranking[i] = i;        // 0,1,2,...,7

for (int pasada = 0; pasada < NUM_ESTRATEGIAS - 1; pasada++)
    for (int k = 0; k < NUM_ESTRATEGIAS - 1 - pasada; k++)
    {
        long long puntajeActual    = estrategias[ranking[k]].puntajeTotal;
        long long puntajeSiguiente = estrategias[ranking[k + 1]].puntajeTotal;
        if (puntajeActual < puntajeSiguiente)          // el de abajo tiene más: intercambiar
        {
            int temporal = ranking[k];  ranking[k] = ranking[k + 1];  ranking[k + 1] = temporal;
        }
    }
¿Por qué ordenar índices y no las fichas? Si se intercambiaran las fichas, estrategias[3] dejaría de ser Tit for Tat. Pero puntosContra[3] de todas las demás sigue significando “contra la estrategia que estaba en la posición 3”. Toda la tabla de resultados quedaría desordenada. Ordenando un arreglo aparte de índices, estrategias[] no se mueve. Además, intercambiar dos int es más barato que intercambiar dos structs con un string y un arreglo dentro.
¿Por qué k < NUM_ESTRATEGIAS - 1 - pasada? Después de cada pasada, el menor puntaje “se hunde” hasta el final y queda en su lugar definitivo. No hace falta volver a compararlo. Y el - 1 evita que k + 1 se salga del arreglo.

Variable¿Por qué existe?
entradaValidaUna bandera (bool) que controla el while: repetir hasta que la entrada sirva.
cin.clear()Cuando cin falla, queda “bloqueado” y todas las lecturas siguientes fallan. clear() lo desbloquea.
cin.ignore(...)Las letras que causaron el error siguen esperando en la entrada. Si no se botan, el cin >> siguiente las vuelve a leer y el programa entra en un bucle infinito.
numeroRondas < MIN_RONDASEs la única comparación: solo se controla el mínimo, porque el enunciado no pone un máximo. Un número que no cabe en un int (más de 2 147 483 647) hace fallar a cin y cae en “Entrada invalida”.

Funciones de salida

  • mostrarDetalleTorneo recorre ranking[] y llama a mostrarDetalleEstrategia(estrategias, ranking[puesto]): el detalle sale en orden de puesto.
  • setw(n) reserva n espacios para el siguiente dato y left/right lo alinean: así la tabla sale en columnas.
  • fixed << setprecision(2) muestra los double con dos decimales (78.40).
  • const Estrategia &estrategia = estrategias[indice]; crea un alias corto para no escribir estrategias[indice]. en cada línea. Es const &: no copia y no permite modificar.
  • mostrarGanador compara con puntajeMaximo para anunciar a todas las estrategias empatadas en el primer lugar, no solo a ranking[0].
